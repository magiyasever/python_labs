# Отчет по лабораторной работе №8

## Описание модели `Student`

Каждый студент хранится в виде словаря такого вида:

```python
{
    "fio": "Иванов Иван Иванович",
    "birthdate": "2007-05-14",
    "group": "БИВТ-26-6-1",
    "gpa": 4.3
}
```

Обязательные поля записи перечислены в кортеже
`STUDENT_FIELDS = ("fio", "birthdate", "group", "gpa")`.

### Создание и валидация

Для создания записи используется функция `make_student(fio, birthdate, group, gpa)`.
Она убирает лишние пробелы в ФИО и названии группы, переводит средний балл
в `float`, после чего проверяет получившийся словарь.

Проверкой занимается функция `validate_student(rec)`. Она убеждается, что на вход
пришел словарь и что его ключи полностью совпадают с `STUDENT_FIELDS`. Поля `fio`
и `group` должны быть непустыми строками. Дата рождения должна быть записана в
формате `YYYY-MM-DD`, быть реально существующей и не позже сегодняшнего дня.
Поле `gpa` должно быть числом от `0` до `5`.

Создадим запись:

```python
from src.lab08.models import make_student

student = make_student(
    "Иванов Иван Иванович",
    "2007-05-14",
    "БИВТ-26-6-1",
    4.3,
)
print(student)
```

Вывод программы:

```Shell
{'fio': 'Иванов Иван Иванович', 'birthdate': '2007-05-14',
 'group': 'БИВТ-26-6-1', 'gpa': 4.3}
```

## Функции для работы с моделью

`make_student(...)` создает запись студента и сразу ее проверяет.

`validate_student(rec)` проверяет структуру и значения уже готовой записи.

`student_age(rec, today=None)` считает, сколько полных лет студенту.

`format_student(rec)` собирает строку из ФИО, группы, возраста и GPA.

`student_to_dict(rec)` возвращает проверенную копию записи.

`student_from_dict(d)` восстанавливает запись из словаря: берет только нужные
поля, переводит `gpa` в `float` и проверяет результат.

`update_student(rec, **fields)` является дополнительной функцией. Она создает новую
запись с измененными полями, а исходный словарь оставляет без изменений.

Пример вывода записи в читаемом виде:

```python
from src.lab08.models import format_student

print(format_student(student))
```

Что получается:

```text
Иванов И.И. (БИВТ-26-6-1), 18 лет, GPA 4.30
```

Возраст можно посчитать и относительно конкретной даты:

```python
from src.lab08.models import student_age

print(student_age(student, "2026-05-13"))
```

Проверим, что `update_student` не трогает исходную запись:

```python
from src.lab08.models import update_student

updated = update_student(student, gpa=4.8)

print(student["gpa"])  # 4.3
print(updated["gpa"])  # 4.8
```

Если передать поле, которого нет в модели, будет выброшен `KeyError`. Если же
новое значение не проходит проверку, возникает `ValueError`.

## Работа с JSON

### Сохранение в JSON

Функция `students_to_json(students, path)` получает список или кортеж записей,
проверяет каждую из них и записывает в файл массив объектов. Файл сохраняется
в кодировке UTF-8 с параметром `ensure_ascii=False` и отступом в два пробела.

```python
from src.lab08.models import make_student
from src.lab08.serialize import students_to_json

students = [
    make_student("Иванов Иван Иванович", "2007-05-14", "БИВТ-26-6-1", 4.3),
    make_student("Петрова Анна Сергеевна", "2006-11-02", "БИВТ-26-6-1", 4.8),
]

students_to_json(students, r"data\lab08\students_output.json")
```

Так выглядит JSON перед тем, как запись превращается в объект Python:

```json
[
  {
    "fio": "Иванов Иван Иванович",
    "birthdate": "2007-05-14",
    "group": "БИВТ-26-6-1",
    "gpa": 4.3
  }
]
```

После чтения и десериализации мы снова получаем список словарей `Student`
с теми же четырьмя полями.

### Загрузка из JSON

Функция `students_from_json(path)` читает файл, проверяет, что в корне лежит
список, и затем передает каждую запись в `student_from_dict`.

```python
from src.lab08.serialize import students_from_json

students = students_from_json(r"data\lab08\students_input.json")
for item in students:
    print(item)
```

При чтении JSON применяется строгий режим (`strict`). Если хотя бы одна запись
оказывается неправильной, загрузка останавливается и выбрасывается `ValueError`,
в котором указан номер записи и причина ошибки. Я решил не пропускать
некорректные записи, чтобы повреждения во входном файле не оставались
незамеченными.

Например, если у записи `gpa = 7`, сообщение будет таким:

```text
ValueError: Ошибка при записи №1: Поле 'gpa' должно быть в диапазоне от 0 до 5, получено: 7
```

Если файла нет, выбрасывается `FileNotFoundError`. Если в корне JSON лежит
не список, выбрасывается `ValueError`.

## Чтение из CSV (дополнительно)

Функция `students_from_csv(path)` рассчитана на CSV файл со следующим заголовком:

```text
fio,birthdate,group,gpa
```

Так как `csv.DictReader` возвращает все значения строками, поле `gpa`
сначала переводится в `float`, а уже потом запись передается в
`student_from_dict`. Дальше она проверяется так же, как и любая другая.

Здесь тоже используется строгий режим. Неправильный заголовок, лишний столбец,
GPA, который не является числом, или любая другая ошибка в строке
останавливают чтение, и выбрасывается `ValueError` с номером проблемной строки.

## Проверка

Для проверки можно запустить из корня репозитория такой код:

```python
from src.lab08.serialize import students_from_json, students_to_json
from src.lab08.models import format_student

students = students_from_json(r"data\lab08\students_input.json")
for st in students:
    print(format_student(st))

students_to_json(students, r"data\lab08\students_output.json")
```

Помимо этого я проверил создание корректной записи через `make_student`,
подсчет возраста, форматирование записи и копирование через `student_to_dict`.
Также проверил, что при обновлении GPA исходный словарь не меняется, а список
студентов корректно сохраняется в JSON и читается обратно. Отдельно убедился,
что программа отклоняет несуществующую дату `2003-02-30`, дату рождения из
будущего, GPA вне диапазона `0..5` и JSON с некорректной записью.
