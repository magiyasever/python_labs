# ЛР9. Хранилище студентов в CSV и консольная утилита

## Цель работы

Реализовать добавление, чтение, обновление и удаление записей студентов в CSV. Консольная программа вызывает функции хранилища через подкоманды argparse.

## Хранилище и результаты

В файле [`group.py`](group.py) находятся функции хранилища. Путь к CSV-файлу передаётся каждой из них первым аргументом, поэтому одни и те же функции можно применять к разным файлам. Если файла ещё нет, `ensure_storage(path)` создаёт его вместе с папками и записывает строку-заголовок. Чтение выполняется через `csv.DictReader`, запись через `csv.DictWriter`.

В файле [`cli_students.py`](cli_students.py) находится консольная программа с подкомандами `add`, `list`, `find`, `update`, `remove` и `stats`. Записи выводятся функцией `format_student` из ЛР8.

Данные хранятся в [`students.csv`](../../data/lab09/students.csv) в кодировке UTF-8, первая строка файла содержит заголовок `fio,birthdate,group,gpa`. При чтении значение GPA переводится из строки в `float`, после чего каждая запись проверяется функцией `student_from_dict` из ЛР8. Файл с отсутствующим или неверным заголовком не принимается, строки с лишними или недостающими значениями тоже. В сообщении об ошибке указывается номер строки файла.

Изменяющие операции загружают весь файл в список словарей, меняют список в памяти и сохраняют файл целиком. Сохранение идёт через временный файл, который потом заменяет старый, поэтому сбой во время записи не портит базу. Команды `list` и `find` файл только читают.

Сортировка по ФИО и по GPA выполняется по возрастанию, при сортировке по ФИО регистр не учитывается, а буквы е и ё считаются одинаковыми. Поиск ищет подстроку в ФИО тоже без учёта регистра. Команда `update` меняет первую запись с указанным ФИО, а `remove` удаляет все записи с таким ФИО и сообщает, сколько их было.

Команды запускаются из корня репозитория. По умолчанию используется файл `data/lab09/students.csv`. Другой файл можно указать опцией `--db` после названия подкоманды.

```bash
python -m src.lab09.cli_students list --db data/lab09/students.csv
```

## Сценарий из шести команд

Перед запуском в базе лежат две записи из раздела «Итоговый CSV». Сценарий добавляет третью запись, поднимает её GPA с 4.10 до 4.60 и после этого удаляет её. Возраст в выводе считается на день запуска.

### Добавление

```bash
python -m src.lab09.cli_students add --fio "Кузнецова Анна" --birthdate 2007-04-02 --group БИВТ-26-6-1 --gpa 4.1
```

```text
Добавлен: Кузнецова А. (БИВТ-26-6-1), 19 лет, GPA 4.10
```

### Список без сортировки

```bash
python -m src.lab09.cli_students list
```

```text
Иванов И. (БИВТ-26-6-1), 19 лет, GPA 4.30
Петрова М. (БИВТ-26-6-2), 19 лет, GPA 4.80
Кузнецова А. (БИВТ-26-6-1), 19 лет, GPA 4.10
```

### Поиск по части ФИО

```bash
python -m src.lab09.cli_students find --q КУЗНЕЦ
```

```text
Кузнецова А. (БИВТ-26-6-1), 19 лет, GPA 4.10
```

### Изменение GPA

```bash
python -m src.lab09.cli_students update --fio "Кузнецова Анна" --gpa 4.6
```

```text
Обновлён: Кузнецова Анна
```

### Список, отсортированный по GPA

```bash
python -m src.lab09.cli_students list --sort gpa
```

```text
Иванов И. (БИВТ-26-6-1), 19 лет, GPA 4.30
Кузнецова А. (БИВТ-26-6-1), 19 лет, GPA 4.60
Петрова М. (БИВТ-26-6-2), 19 лет, GPA 4.80
```

### Удаление

```bash
python -m src.lab09.cli_students remove --fio "Кузнецова Анна"
```

```text
Удалено записей: 1
```

## Проверка неверного GPA

```bash
python -m src.lab09.cli_students add --fio "Кузнецова Анна" --birthdate 2007-04-02 --group БИВТ-26-6-1 --gpa 99
echo $?
```

```text
Ошибка: gpa: ожидалось 0..5, получено 99.0
1
```

Текст ошибки печатается в `stderr`, программа завершается с кодом `1`. Запись в файл не попадает, его содержимое не меняется.

## Дополнительное задание

Функция `stats(path)` считает число студентов, минимальный, максимальный и средний GPA, количество студентов в каждой группе и составляет список из пяти лучших по GPA. Если база пуста, вместо значений GPA возвращается `None`, а словарь групп и список лучших остаются пустыми. Подкоманда `stats` выводит эти данные в консоль.

```bash
python -m src.lab09.cli_students stats
```

```text
Всего студентов: 2
GPA: min 4.30, max 4.80, средний 4.55
По группам:
  БИВТ-26-6-1: 1
  БИВТ-26-6-2: 1
Топ-5:
  1. Петрова Мария — 4.80
  2. Иванов Иван — 4.30
```

Кроме того, `add_student` не добавляет запись, если студент с таким ФИО уже есть в базе. В этом случае файл остаётся прежним.

```bash
python -m src.lab09.cli_students add --fio "Иванов Иван" --birthdate 2007-10-10 --group БИВТ-26-6-1 --gpa 4.9
echo $?
```

```text
Ошибка: fio: студент 'Иванов Иван' уже есть
1
```

## Теория

CRUD обозначает четыре основные операции над данными. Create отвечает за добавление записи, Read за чтение списка и поиск, Update за изменение записи, Delete за удаление.

CSV хранит данные как обычный текст, строки в нём разной длины, поэтому изменить одну запись прямо внутри файла нельзя. По этой причине изменяющие операции читают весь файл в список словарей, меняют список и записывают файл заново. Путь к файлу передаётся в функции явно, так что функции не хранят состояние сами и могут работать с любым CSV.

`DictReader` отдаёт все значения строками. Если оставить GPA строкой, сравнение пойдёт посимвольно и `"4.3"` окажется больше `"10.0"`. Поэтому при чтении GPA сразу переводится в число, и после этого сортировка работает правильно, а к записи можно применить проверку из ЛР8. Параметр `newline=""` оставляет обработку переводов строк модулю `csv`, а кодировка UTF-8 нужна для кириллицы в ФИО и названиях групп.
